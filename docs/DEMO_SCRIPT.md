# Five-minute demo script

Record the screen at 1080p with the live URL. Open the site a minute before so a sleeping free instance has woken up. Talk over each step; the times are targets.

**0:00–0:25 — The promise.** Home page: sign in, or create a user, either an account holder (₹0 account, ready at once) or an auditor, which is only a request until an administrator approves it. "LedgerLine moves money so the books always balance, the same request never pays twice, and you can prove what happened. This seal is drawn from the live ledger's latest hash: change any past entry and it changes."

**0:25–1:10 — A normal payment, and its proof.** Sign in as **Priya**. Accounts → Send money → pay `LL-1003` ₹750 ("Pays Rahul Verma" confirms the payee). Point at the request key: "if this is sent twice, it pays once." Open the statement: debit, running balance, initiated by. Click the row: hash, previous hash, signature, "Hash and signature verified".

**1:10–2:10 — Attack the money (Race Lab).**
* Overdraw race: 10 transfers at once that together exceed the balance. The result shows how many were paid, how many were refused for lack of money, and that the balance never went below zero. "Each request checks the balance while holding a lock on the account row; the database re-checks the floor itself."
* Replay storm: one request ×12 with the same key. 1 journal entry, 11 answered from storage, identical bodies.

**2:10–2:50 — Steal and mint, from a terminal.** Run `python tools/attack.py --url <live-url>` and scroll the scorecard: two withdrawals at once, a burst of 25, a replay ×20, key reuse, another user's money, minting, malformed amounts, forged tokens, PUT/DELETE on the ledger, deadlock bait, signing up as an admin, asking for auditor access and trying to use it before approval, a second administrator trying to make more administrators or lock out the main one. Final line: auditor's proof passes, sum of balances 0.

**2:50–3:40 — AI flags, a person decides.** As Priya, send ₹1,10,000 from Savings to a new payee: "held for review", and the money is reserved. Sign in as **Admin** → Reviews. Score dial and reasons ("moves 92% of the available balance", "first payment to this payee"). Click **Ask AI for a note**: the note, with a line saying every number was checked against the facts. Approve with a note. "The suggestion, the AI note and my decision are three separate signed entries. The AI never moves money: it cannot even import the code that does." Then **Users**: Meera's auditor request is waiting. Approve it: "only now can she sign in, and the database would refuse this decision from anyone but an administrator." Point at the *main admin* tag: "any administrator can do this work, so nothing waits for me, but only I, the main administrator, can create administrators or remove one, and nobody can remove me." If there is time: Rahul's personal details are waiting, so click **Check details** and **Verify version 1**. "Only another administrator can verify them, and only the version I saw. The journal records that I verified it, never the address itself."

**3:40–4:30 — Prove it.** Sign in as **Auditor** → Proof. The seal draws itself; all 15 checks pass: chain, signatures, double entry, replay, floors, conservation ("inside LedgerLine = in − out"), suspense, exactly-once, access (every user's role matches its signed creation; administrators only from the main administrator), personal details (changed only by their owner, checked only by another administrator), backstop never fired. Show Duplicates: every replay listed. Download the evidence bundle and run `python tools/verify_bundle.py ledgerline-evidence.json --public-key …`: VERIFIED, with no access to the server.

**4:30–5:00 — Tamper, and get caught** (pre-recorded clip, or local). In psql as the DB owner: disable the append-only trigger, change one memo, then run Proof: "Hash chain broken at entry #N". Close with `python tools/mutation_check.py` output: "47 of 47 removed locks and checks are caught by our tests." Mention THREATS.md and the open risks you chose to accept.
